# Selectable Designs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The tablet app offers three designs — Standard (today), Kreidetafel and Bierdeckel —
chosen per tablet in the admin area; the two new designs bring their own drink selection,
name list, undo banner, quantity sheet and screensaver (issue #4).

**Architecture:** A pure `AppDesign` enum is stored in the existing app config store and exposed
through Riverpod; each design supplies a `DesignTokens` `ThemeExtension` (colours, fonts, tier
palette) that drives `ThemeData`. Screens keep their state and behaviour and only swap the
*view* widget per design. The two non-trivial layouts (coaster rings, chalk fields) are pure,
unit-tested planning functions; widgets only render their plans.

**Tech Stack:** Flutter + Riverpod (+ existing Drift config store), bundled OFL fonts.

**Spec:** `docs/superpowers/specs/2026-11-07-themes-design.md` (all sections). Main spec:
`docs/superpowers/specs/2026-11-02-bar-tab-design.md` §4. Approved mockups (git-ignored, for
look reference only): `.superpowers/brainstorm/272336-1794048650/content/` — `layouts-v2.html`
option B (Kreidetafel drinks), `bierdeckel-v2.html` (rings + tray), `namelist-v1.html`,
`bierdeckel-bg.html` card "Grüner Tresen", `bierdeckel-halo.html` variant 1, `sheet-saver.html`.

## Global Constraints

- App only. No server, API or Drift schema change (the design lives in the existing
  `app_config` key/value table).
- TDD; never weaken existing tests. Existing tests may be *parameterised over designs* (run once
  per design) — that adds coverage and is allowed.
- Every UI string in `app/lib/l10n/app_de.arb` (German). New strings: `designTitle` "Design",
  `designStandard` "Standard", `designKreidetafel` "Kreidetafel", `designBierdeckel`
  "Bierdeckel", `favouritesChalk` "Für dich", `favouritesTray` "Deine Favoriten".
- No `DateTime.now()` outside the clock wrapper.
- Standard must look and behave exactly as today; its existing widget tests stay unchanged.
- Every design keeps the existing widget keys so behaviour tests run unchanged per design:
  `drink-<id>`, `quick-<id>`, `keypad-<n>`, `keypad-crate`, `keypad-backspace`,
  `quantity-field`, `quantity-minus`, `quantity-plus`, `undo-banner-progress`,
  `order-bar-progress`, `screensaver-hint`, `admin-gear`. Name tiles stay findable by name text.
- Performance (rk3399): animate only opacity/transform; no `BackdropFilter`; textures are
  painted once (e.g. `CustomPainter` with `shouldRepaint => false` under a `RepaintBoundary`,
  seeded deterministic speckle) — never per frame.
- Fonts bundled as assets with their OFL licence files in `app/assets/fonts/` and registered via
  `LicenseRegistry` (as Archivo is today, if it is; otherwise add it for all): Caveat
  (Kreidetafel), Alfa Slab One + Barlow Condensed (Bierdeckel). Standard keeps Archivo.
- Colours (spec §4.3/§4.4): chalk board `#3a403c`→`#232724`, frame `#7a5534`, chalk `#f4f1e8`,
  yellow chalk `#f7d774`; counter `#2f5a47`→`#17322a`, coaster `#f3e7cf`, accent `#7a1f1f`, gold
  rim `#d9a441`. Group colours come from data (`DrinkGroup.color`); tier colours from each
  design's own index palette.
- Coaster sizes ≥ 44 design px; overflow only ever scrolls vertically; no group is ever hidden.
- `app/tool/check.sh` clean before every commit. Conventional Commits, `Refs #4`, trailer
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Person with 0–3 favourites** in a new design — the favourites column shows only those
   (larger spacing), and with none it is hidden and the board uses the width. Tests in Tasks 5, 6.
2. **Very long names** (a 20+ character single word, a name beyond the maximum length) — no
   RenderFlex overflow, single word shrinks to the minimum then ellipsis. Tests in Tasks 4, 5, 7.
3. **Large assortments** (8 groups; one group with 30 drinks) — every drink is reachable by
   vertical scrolling, none hidden. Unit tests in Tasks 2, 3; widget smoke tests in Tasks 5, 6.
4. **Design switched in admin** — after leaving admin the name list and the next drink screen
   use the new design without restart; the choice survives an app restart. Test in Task 1.
5. **Pending grid order in a new design** — the favourites are inert and dimmed exactly like
   today's quick bar. Tests in Tasks 5, 6.

### Task 2: Coaster ring planning (pure)

**Files:**
- Create: `app/lib/presentation/design/coaster_plan.dart` (pure Dart, `dart:math` only, plus
  `dart:ui` `Size`/`Rect`)
- Test: `app/test/presentation/design/coaster_plan_test.dart`

**Interfaces:**
- Produces:
  ```dart
  const kCoasterSteps = [72.0, 60.0, 50.0];   // design px, largest first
  const kCoasterGap = 8.0;
  class Ring { final double radius; final int count; }
  class GroupRings { final double coaster; final double hub; final List<Ring> rings;
                     double get outerRadius; Size get footprint; }   // footprint = 2*outer + coaster
  GroupRings ringsFor(int count, double coaster, {double gap = kCoasterGap});
  class CoasterBoardPlan { final double coaster; final List<GroupRings> groups;
                           final List<Rect> blocks; final bool scrolls; }
  CoasterBoardPlan planCoasterBoard(List<int> counts, Size area,
                                    {List<double> steps = kCoasterSteps});
  ```
- Rules (spec §4.4) the implementation must follow:
  - hub = `1.35 * coaster`; ring 1 radius `hub/2 + gap + coaster/2`; ring k+1 radius = ring k
    radius `+ coaster + gap`; capacity(r) = `floor(2πr / (coaster + gap))`.
  - Fill rings inside out. When the remaining coasters for a new ring are fewer than 3, they go
    into the previous ring instead, whose radius grows to `n*(coaster+gap)/(2π)` if larger.
  - `planCoasterBoard`: for each step (largest first) compute footprints and pack blocks in group
    order into columns — a block goes below the previous block of the current column if the
    column height still fits `area.height` and the block is not wider than the column; otherwise
    a new column starts. The first step whose total column width fits `area.width` wins
    (`scrolls: false`). If none fits, use the smallest step and wrap columns into rows (row height
    = tallest column), `scrolls: true`. Blocks are centred within their column.

- [ ] **Step 1: Write failing tests:**
  `ringsFor(5, 72)` → one ring of 5; `ringsFor(7, 72)` (capacity 7) → one ring of 7;
  `ringsFor(9, 72)` → one ring of 9 with radius > ring-1 radius of `ringsFor(7, 72)`;
  `ringsFor(10, 72)` → rings `[7, 3]`; `ringsFor(20, 72)` → `[7, 13]`;
  `ringsFor(22, 72)` → `[7, 15]` (2 leftovers stay in ring 2, radius widened);
  `ringsFor(1, 72)` → one ring of 1. Board: counts `[5, 3, 11, 1]` in `Size(1000, 480)` → step
  72, Bier and Alkoholfrei share column 1, no overlap of blocks, `scrolls == false`;
  a board that only fits at 60 picks 60; `[30, 30, 30, 30, 30, 30, 30, 30]` in `Size(1000, 480)`
  → `coaster == 50`, `scrolls == true`, every block inside `x ∈ [0, 1000]`.
- [ ] **Step 2: Run** `cd app && flutter test test/presentation/design/coaster_plan_test.dart` — FAIL.
- [ ] **Step 3: Implement.**
- [ ] **Step 4: Run** — PASS; then `app/tool/check.sh` green.
- [ ] **Step 5: Commit** `feat(app): plan coaster rings for any number of drinks`.

### Task 3: Chalk field planning (pure)

**Files:**
- Create: `app/lib/presentation/design/chalk_plan.dart`
- Test: `app/test/presentation/design/chalk_plan_test.dart`

**Interfaces:**
- Produces:
  ```dart
  const kChalkBoxHeight = 46.0, kChalkBoxGap = 6.0, kChalkHeader = 40.0;
  const kChalkMinFieldWidth = 170.0, kChalkMinBoxWidth = 150.0;
  class ChalkField { final Rect rect; final int boxColumns; final bool scrolls; }
  class ChalkBoardPlan { final List<ChalkField> fields; final bool scrolls; }
  ChalkBoardPlan planChalkBoard(List<int> counts, Size area);
  ```
- Rules (spec §4.3, §5): height need(n, cols) = `kChalkHeader + ceil(n/cols)*(box+gap)`. A field
  gets 2 box columns when its 1-column need exceeds `area.height`; if the 2-column need still
  exceeds it, the field `scrolls`. Pack fields into columns in group order as in Task 2 (stack
  while the column height fits). Column width is shared by weight = max box columns × max count
  in the column, with `kChalkMinFieldWidth` per box column (2-column fields also need
  `2*kChalkMinBoxWidth`). If the minimum widths exceed `area.width`, wrap columns into rows and
  set `scrolls: true` on the plan.

  drinks → `boxColumns == 2`, field `scrolls == true`; 8 groups of 6 in `Size(760, 480)` → plan
  `scrolls == true`, all fields within width.
