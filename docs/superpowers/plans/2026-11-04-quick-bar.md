# Quick Bar Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A row of 4 drinks on the drink selection screen — the person's own most frequent drinks
first, filled up from the overall ranking — where one tap books one unit immediately (issue #2).

**Architecture:** The server counts bookings per (person, drink) and per drink over all periods
and serves them at `GET /api/v1/rankings`. The app fetches them as the last step of every sync,
caches them in a single-row Drift table (schema v4) and merges them in a pure domain function
into the 4 quick-bar drinks. A quick tap goes through `OrderController.quickBook`, which reuses
`commit()` so the undo hold and banner work unchanged.

**Tech Stack:** FastAPI + SQLAlchemy (server), Flutter + Riverpod + Drift + freezed (app).

**Spec:** `docs/superpowers/specs/2026-11-02-bar-tab-design.md` — §4.2 "Quick bar", §5 "Drink
rankings for the quick bar", §2 non-goal, §12 last entry.

## Global Constraints

- Repo English; UI strings only via `app/lib/l10n/app_de.arb` (this plan adds none).
- TDD: failing test first, seen failing for the right reason. Never weaken existing tests; adding
  a provider override to an existing test harness is fine.
- No `datetime.now()` / `DateTime.now()` outside the clock wrapper.
- Every schema change ships a migration and a test (Drift here; the server needs no schema change).
- Server: `server/tool/test.sh` clean (pytest, ruff check, ruff format --check), line length 100.
  Layers: domain pure, persistence, api; dependencies point inward.
- App: `app/tool/check.sh` clean. Generated files are not committed — except the Drift schema
  dumps and `test/data/db/generated/*`, which the repo already commits.
- `api/openapi.json` is committed and checked by `server/tests/test_openapi_contract.py`; the app
  DTO contract test (`app/test/data/api/dto_contract_test.dart`) checks DTOs against it.
- Count = number of bookings (rows), never quantity. Whole history = all periods.
- Quick bar size: 4. Ties: grid order (group sort order, then drink order as in
  `Catalog.drinksFor`). Only drinks the person can book from the grid.
- Conventional Commits; every commit ends with a blank line and
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; reference `Refs #2`.

## Review Focus

1. **Older server without `/rankings` (404) or a rankings error** — the sync must still have
   pushed bookings and refreshed tabs and catalog. Rankings are fetched last; test in Task 4.
2. **Rankings name a drink the catalog no longer has, or one hidden/inactive/without a tier
   price** — it is skipped and the next drink moves up. Test in Task 5.
3. **Double tap on a quick tile** — exactly one booking. Tests in Task 6 and Task 7.
4. **Grid order pending, then "Verwerfen"** — the quick bar is active again. Test in Task 7.
5. **Fast tap right after returning to the name list** — must not open another person. Test in
   Task 8.

### Task 5: App — pick the quick-bar drinks

**Files:**
- Create: `app/lib/domain/quick_bar.dart`
- Test: `app/test/domain/quick_bar_test.dart`

**Interfaces:**
- Consumes: `Catalog`, `Person`, `Drink`, `Catalog.drinksFor`, `DrinkRankings`.
- Produces: `const kQuickBarSize = 4;` and `List<Drink> quickBarDrinks(Catalog catalog, Person
  person, DrinkRankings? rankings, {int size = kQuickBarSize})`.

Algorithm (the tests pin it): candidates = `catalog.drinksFor(person)` flattened, which is already
the bookable set in grid order; `gridIndex[drinkId]` = position there. Own list = candidates with
a count > 0 in `rankings.persons[person.id]`, sorted by count desc, then `gridIndex`. Overall list
= candidates with a count > 0 in `rankings.overall`, same sort, minus the own ones. Result = own
followed by overall, first `size`. `rankings == null` → `[]`. Drinks never booked by anyone do not
appear.

- [ ] **Step 1: Write the failing tests** (catalog with Helles, Cola-Mix, Wasser, Weizen, Pils
  in one tier, plus hidden, inactive and other-tier-only drinks):
  - `a new person gets the overall top 4`: overall {Helles 89, Cola-Mix 50, Wasser 48, Weizen 34,
    Pils 10}, no own entry → [Helles, Cola-Mix, Wasser, Weizen].
  - `own drinks come first, then the overall list without them`: own {Pils 1} →
    [Pils, Helles, Cola-Mix, Wasser].
  - `own drinks are ranked by their own count`: own {Wasser 1, Weizen 5} → [Weizen, Wasser,
    Helles, Cola-Mix].
  - `ties follow the grid order`: overall {Weizen 3, Helles 3} with Helles before Weizen in the
    grid → Helles first; same for own ties.
  - `drinks the person cannot book are skipped`: hidden, inactive, no price for the tier and an id
    unknown to the catalog all ranked top → none of them in the result, next drinks move up.
  - `fewer ranked drinks give a shorter list`: overall {Helles 1} → [Helles].
  - `no rankings give an empty list`: `rankings == null` and empty maps → [].
