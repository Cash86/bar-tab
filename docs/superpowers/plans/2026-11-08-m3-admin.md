# Milestone 3 — Admin Area Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The admin maintains persons, drinks, groups and price tiers, records and cancels
deliveries, books events, changes the PIN and re-pairs the tablet (also offline) from the tablet;
the header total no longer flickers.

**Architecture:** Server: Alembic `0003` adds storno columns to `stock_entries`; pure name rules
in `bartab/domain/names.py`; master-data, delivery and PIN repositories in new persistence
modules; three new admin route modules behind `require_admin`. App: new API calls and DTOs, plain
admin screens (one file per screen under `presentation/admin/`), one shared quantity list for
delivery and event booking, a local PIN hash in the existing `AppConfig` key-value table (no
Drift schema change), re-pairing reuses `Pairing.pair`, and the running total becomes one Drift
query.

**Tech Stack:** FastAPI + SQLAlchemy + Alembic (server); Flutter + Riverpod + freezed + Drift
(app); new app dependency `cryptography` (PBKDF2).

**Spec:** `docs/superpowers/specs/2026-11-08-m3-admin-design.md` (all sections), main spec
`docs/superpowers/specs/2026-11-02-bar-tab-design.md` §3, §4.3, §10.

## Global Constraints

- Repo English; every UI string via `app/lib/l10n/app_de.arb` (German). No hard-coded strings.
- TDD: failing test first, seen failing for the right reason. Never weaken or delete existing tests.
- No `datetime.now()` / `DateTime.now()` outside the clock wrapper; take a `Clock`.
- IDs UUID4 strings; `created_at`/`updated_at` UTC, timezone-aware, set from the clock; money
  integer cents.
- Every schema change ships a migration and a test: Alembic `0003` (stock entry storno). No Drift
  schema change in this milestone (`schemaVersion` stays 4).
- Maximum lengths (characters = code points, after trimming): person 20, drink 24, group 16,
  tier 16. Empty after trimming is invalid.
- Names unique per kind, compared with `str.casefold()` after trimming, deactivated entries
  included.
- Server: `server/tool/test.sh` clean (pytest, ruff check, ruff format --check), line length 100;
  layers domain → persistence → api, dependencies point inward.
- App: `app/tool/check.sh` clean; generated files not committed.
- `api/openapi.json` is regenerated with `server/tool/export_openapi.py` whenever routes or
  schemas change; `app/test/data/api/dto_contract_test.dart` covers every new DTO.
- Admin endpoints use `require_admin` (`X-Admin-Token`), event bookings use the existing
  `POST /bookings` (device auth). Admin functions online-only, except re-pairing.
- Error details (exact strings): 404 `not_found`; 409 `name_taken`, `group_in_use`,
  `tier_in_use`, `last_tier`, `order_mismatch`, `delivery_conflict`, `already_cancelled`,
  `period_closed`; 422 `invalid_name`, `unknown_reference`, `prices_incomplete`,
  `invalid_quantity`; PIN change 403 `wrong_pin`, 429 `locked` (body as login).
- Conventional Commits; every commit ends with a blank line and
  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Admin saves a drink while a tier was just added on another tablet** — the prices map no
   longer matches the tiers: 422 `prices_incomplete`, the app reloads the catalog and keeps the
   dialog open. Test in Task 3 (server) and Task 9 (dialog keeps values on error).
2. **"Lieferung buchen" tapped twice or retried after a timeout** — the same client UUIDs make the
   second request a no-op; never 2× stock. Tests in Task 4 and Task 11.
3. **Admin types a name with surrounding spaces or a different case of an existing name**
   ("pils 0,5 " vs "Pils 0,5") — trimmed and refused as `name_taken`. Tests in Task 2.
4. **Re-pair attempt with a typo in the URL** — validation fails, the old pairing, queue and
   caches stay untouched, the app keeps working with the old server. Test in Task 15.
5. **Tablet idles in the offline repair-only admin** — the 2-minute idle ends the local unlock
   just like an admin session. Test in Task 15.

**Files:**

**Interfaces:**

- Produces in `persistence/master_data.py` (all take `session: Session`, `clock: Clock` where they
  write; all raise the exceptions below; all set `created_at`/`updated_at` from the clock):
  ```python
  class NotFound(Exception): ...
  class Conflict(Exception):        # .detail: one of name_taken, group_in_use, tier_in_use,
      def __init__(self, detail: str) -> None   # last_tier, order_mismatch
  class Invalid(Exception):         # .detail: invalid_name, unknown_reference, prices_incomplete
      def __init__(self, detail: str) -> None
  def create_person(session, clock, *, name, price_tier_id, is_hidden, is_collective) -> Person
  def update_person(session, clock, person_id, *, name, price_tier_id, is_hidden, is_collective,
                    is_active) -> Person
  def create_drink(session, clock, *, name, group_id, crate_size, is_hidden,
                   prices: dict[str, int]) -> Drink          # sort_order = max in group + 1
  def update_drink(session, clock, drink_id, *, name, group_id, crate_size, is_hidden, is_active,
                   prices: dict[str, int]) -> Drink          # group change → end of new group
  def create_group(session, clock, *, name, color) -> DrinkGroup        # appended
  def update_group(session, clock, group_id, *, name, color) -> DrinkGroup
  def delete_group(session, group_id) -> None                 # Conflict("group_in_use")
  def create_tier(session, clock, *, name) -> PriceTier       # appended; copies first tier's prices
  def update_tier(session, clock, tier_id, *, name) -> PriceTier
  def delete_tier(session, tier_id) -> None   # Conflict("tier_in_use" | "last_tier"); drops prices
  def reorder_groups(session, clock, ids: list[str]) -> None
  def reorder_tiers(session, clock, ids: list[str]) -> None
  def reorder_drinks(session, clock, group_id: str, ids: list[str]) -> None
  ```
  Reorder: `ids` must be exactly the current set (groups / tiers / drinks of that group incl.
  deactivated), else `Conflict("order_mismatch")`; rewrites `sort_order` 0..n-1 and `updated_at`.
  Uniqueness: compare `name_key` against all rows of the kind except the row itself (Python-side;
  no DB constraint). `prices` must have exactly the current tier ids, each `0 <= cents <=
  1_000_000`, else `Invalid("prices_incomplete")`. Unknown `price_tier_id` / `group_id` →
  `Invalid("unknown_reference")`. Colour format and crate size are validated by the pydantic
  schemas in Task 3; the repository trusts them.
  `updated_at` changes on every write so the catalog ETag changes.
